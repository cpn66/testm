Содержание (резюме обсуждения)

1) Что делает ML‑сервер
- Запускается main.py → цикл опрашивает RabbitMQ.
- При сообщении CreateTask (от Backend) берет documentId и пути к файлам из settings.ini, собирает страницы (pdf2image) или изображения.
- Выполняет инференс/анализ: EasyOCR (reader), pytesseract, детектор формул (MathDetector / pix2tex), детектор таблиц, ImageDetector и прочие модули.
- Формирует структуру страниц/блоков, сохраняет извлечённые изображения/формулы в общую папку (graphics), формирует JSON/XML через paginate/ocrToPdf.
- Отправляет статусные сообщения в Backend через RabbitMQ (UpdateTask) и использует Backend REST API (modules/connect_api.py) для получения типов документов и авторизации.

2) Как общается с backend
- RabbitMQ: чтение из queue_from, публикация в queue_to; в заголовках используются type/from/to (CreateTask / UpdateTask).
- HTTP API: POST /login для получения токена и GET /documentTypes; токен хранится в памяти и используется в заголовках X-Auth-Token.
- Файловая интеграция: входные PDF и выходные артефакты лежат в общем файловом хранилище (путь из settings.ini).

3) Какие модели/модули запускаются локально
- EasyOCR (PyTorch), pytesseract (Tesseract), pix2tex, TensorFlow (в requirements указан tensorflow==2.15.0), onnxruntime и собственные детекторы (MathDetector, TableDetector и пр.). Инференс выполняется прямо в Python‑процессе сервера (опционально GPU ускорение).

4) Возможность переноса на корпоративную платформу ИИ
- Да — варианты: контейнеризация сервиса (Docker/K8s), вынесение инференса в model serving (Triton/KFServing) или адаптация архитектуры для централизованного хранения/очередей.

5) Требования к корпоративной платформе
- Поддержка Python runtime и pip‑зависимостей или возможность запуска контейнеров.
- Поддержка TF/PyTorch/onnxruntime (или запуск контейнеров с этими библиотеками).
- NVIDIA GPU + драйверы (CUDA/cuDNN) для приемлемой производительности.
- Наличие RabbitMQ или возможность адаптации на другой MQ/шину сообщений.
- Общий файловый том или объектное хранилище (S3) для входных PDF и выходных артефактов.
- Менеджер секретов для безопасного хранения credentials (вместо plaintext settings.ini).
- Средства логирования, мониторинга и планирования фоновых задач.

6) Рекомендации при переносе
- Контейнеризовать сервис, включив системные зависимости (tesseract, poppler, шрифты, CUDA libs).
- По возможности конвертировать тяжёлые модели в ONNX для унифицированного сервиса инференса.
- Заменить локальные файловые пути на монтируемые тома или S3 и обновить код (ocrToPdf, save_img, пути в settings.ini).
- Обновить modules/rabbitMQ.py при смене MQ.
- Хранить секреты в менеджере секретов и передавать их через окружение/секреты платформы.

7) Ориентировочные ресурсы
- CPU: 4+ vCPU; RAM: 16–32 GB; SSD; GPU рекомендован (например T4/A10/RTX‑класс) для ускорения.

8) Что означает "PDF → страницы" (pdf2image)
- Это означает, что PDF-файл превращается в список растровых изображений, по одному на страницу.
- Библиотека pdf2image рендерит PDF в JPG/PNG, обычно через Poppler (pdftoppm/pdftocairo).
- Затем полученные изображения передаются в OCR и детектор формул/таблиц/изображений.
- В коде это видно в easy.py: convert_from_path(pdf_name, fmt="jpg", dpi=dpi) возвращает список страниц как изображения.
- DPI (dots per inch) влияет на качество распознавания: чем выше dpi, тем выше детализация, тем больше размер и потребление ресурсов.
- Используется для унифицированной обработки: OCR и другие модули работают с пикселями, а не с PDF-командами.
- Для качественного распознавания текста и формул часто нужен dpi ~200–300.
- Для контейнеризации важно установить Poppler, Tesseract, шрифты и системные библиотеки.
